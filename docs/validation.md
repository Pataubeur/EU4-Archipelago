# Validation status — 2026-11-11

Release candidate **0.5.0** targets Windows Archipelago **0.6.7** and EU4
**1.37.5.0**, normal and Ironman. This is not yet an accepted live-game release.

## 0.5.0 live deliveries — 2026-11-11

Items can now be received live, Ironman included, by entering a 4-digit code in
game (design: [architecture.md](architecture.md#live-deliveries-no-relaunch-ironman-included)).
Not observed in EU4; experiment **E9** pending.

- **Repository suite: 125 tests, 123 passed, two skipped**, no failures. New
  `tests/test_deliveries.py`: code uniqueness and determinism, manifest round trip
  and invalid deliveries, matching by sender/location and start inventory,
  lint of the claim effects, digit-pad events and customizable localisation, shared
  claim/inbox flags, claim audit (claimed before reception, unknown code, trap
  before 1450), DeathLink codes. It exposed and fixed a game.log reader bug: kinds
  containing `_` (`CLAIM_UNKNOWN`) were ignored.
- **Real AP 0.6.7** (fresh copy `local/v050-live/`): frozen check passed (BYZ), and
  the 15-player matrix generated. For all 14 schema-2 slots, the delivery list
  equals exactly the items the spoiler assigns to that slot (35 to 115 per slot;
  20 DeathLink codes for the DeathLink slot). The classic slot has none.

## 0.5.0 implementation — 2026-11-11

Schema 2 (ambitions, fetters, region keys, seals, missions, traps, DeathLink,
game.log channel, mod inbox, formation-aware bridge) is implemented as a
**candidate**. Nothing below was observed in EU4; the acceptance protocol is in
[manual-validation.md](manual-validation.md) (E1–E8 and the 0.5.0 table).

Executed checks:

- **Repository suite at that stage: 114 tests, 112 passed, two skipped** (PyYAML, `AP_ROOT`), no
  failures. New: `tests/test_progression.py` (catalogue uniqueness and stable legacy
  IDs, planning matrix of 22 countries × 3 lengths × 2 modes × 4 goals, option
  variants, static beatability, AP-guard/mod-guard equality, lint of every generated
  script, localisation coverage) and `tests/test_ironman.py` (game.log rotation and
  partial lines, inbox staging only while EU4 is closed, Ironman console file,
  mode and date warnings, DeathLink deduplication, formation in saves, log/save
  rollback interplay, client install and Ironman session, slot-data validation).
- A deliberately reintroduced generator bug (ratify decision missing
  `has_country_flag =`) made 25 tests fail; the generator was restored.
- **Real AP 0.6.7 (frozen Windows runtime, fresh copy `local/v050-final/`)**:
  `check_archipelago.py --frozen --country BYZ` passed: custom world loaded,
  YAML template exported, seed generated (BYZ, standard, mixed, *Basileus*,
  73 locations, keys Anatolia/Balkans), Launcher client UI started.
- **15-player EU4 multiworld** generated by the real generator with four seeds
  (777, 1001–1003): FRA Ironman long with all fetters, 30 % traps and DeathLink;
  BYZ Pentarchy; POR short; MNG with Domination; K00 bare; SWE hard; HAB
  ambition-only; ENG great power; TUN domination; CAS classic charters (schema 1);
  MAL with exclusions; AZT with El Dorado; ARA long with DLCs and double rewards;
  BRA Prussia; ETH Ironman long. All manifests validated and rendered. In the
  seed-777 spoiler, none of the 196 excluded EU4 locations holds a progression
  item, and POR's early keys sit before 1500 (Calendar 1490, a first-row mission).
- The first matrix run exposed a design flaw: AP "early" means sphere 1, not
  early game time, so a dated goal's keys landed on *Calendar: 1530*. Dated goals
  lost their deadline (bonus check excluded), and the last third of the calendar
  is now excluded from progression by default.

Not executed: AP source `WorldTestBase` suite (`apworld/eu4/test`, updated for
0.5.0; needs `AP_ROOT`), a live server session, any EU4 run, no-DLC play.

## Progression and Ironman feasibility — 2026-11-11

Design: [design-progression.md](design-progression.md). Nothing below is a
live-game test unless stated; in-game experiments E1–E8 are **pending** and
prepared in [manual-validation.md](manual-validation.md).

Static evidence from the local EU4 1.37.5.0 install and user directory
(read-only, nothing copied into the repository):

- `checksum_manifest.txt` covers `common/`, `events/`, `missions/`,
  `decisions/`, `history/` and `map/`, not `localisation/`. An inbox under
  `common/scripted_effects/` therefore changes the checksum on every reinstall (E2).
- The native `log` effect exists (16 vanilla uses, with `[Root.GetName]` and
  `[GetYear]` substitutions). Output destination and Ironman behaviour: E1.
- `game.log` is overwritten at each launch (no `game_old.log`); the log
  channel must replay its state.
- Zipped saves on this machine (`Byzance.eu4`, `France.eu4`) contain a binary
  `gamestate` (`EU4bin`). The ZIP-with-text branch of the bridge may match no
  1.37.5 output; normal mode should require uncompressed saves.
- **Existing real-game evidence, previously unrecorded**: `ap_campaign.eu4`
  (FRA, 1445-11-19, EU4txt) contains the binding flag, three check flags, item
  flags 0–3, three charter flags and the goal flag; `ap_multiworld.eu4` and the
  autosave contain a binding flag. Decisions, scan and reward effects therefore
  set their flags in EU4. Exact amounts, console rereading and the client → server
  path remain unproven by these files.
- `started_in`, used by the bind decision, has no vanilla use. The bind decision
  did execute in the saves above; whether it rejects other start dates is E8.
- Mission trees depend on DLCs (`potential_on_load`); without DLC, BYZ has 10
  missions, TUR 23, POL 14, MAL/ETH/AZT/SER none. 4,813 mission IDs, all unique.
- Vanilla uses `diplomats = -1`, `merchants = -1`, `missionaries = -1`; no
  negative `colonists` (E6). `has_won_war`, `num_of_unions`,
  `num_of_completed_idea_groups`, `add_reform_progress` and `create_missionary`
  do not exist in vanilla scripts; the design uses existing equivalents.
- Pacing from dated Khmer saves (one player): ~11–18 in-game years per hour.

Tooling added: `scripts/feasibility_kit.py` (test mod, inbox generations, log
snapshots and report) and `tests/test_feasibility_kit.py`. **66 repository tests:
64 passed, two skipped** (same skips as before), no failures. A dry-run install
into a scratch user directory probed 142 mission IDs for BYZ/ROM; the kit was not
installed in the real EU4 user directory.

## Named country selector — 0.4.1

- Starting Country is now a standard Choice dropdown with 58 alphabetically
  named shortcuts, displaying France (FRA) by default. Other country uses a
  prefilled tag in a separate collapsed advanced group. The shortlist is not
  an exhaustive set of all playable countries.
- **61 repository tests: 59 passed, two skipped**, no failures. Catalogue tests
  cover name/label resolution, unique stable IDs, legacy IDs and unlisted tags.
  The source-gated World tests additionally cover Other country and ignoring an
  inactive custom field; they are not counted as executed here.
- In `local/country-selector-041/`, the actual stock Windows 0.6.7 Options Creator
  executable displayed the named selector; a validation-only APWorld probe checked
  the France default, absence of the old TextChoice input, 58 labels plus Other,
  selected Ming through the real menu callback and exported YAML through the
  official action. Screenshots and JSON/YAML evidence are under `eu4-validation/`.
  Early probe attempts failed to inspect still-collapsed widgets; opening their
  panels fixed the test harness. These were probe setup failures, not game tests.
- Names from the shortlist (e.g. France) now work in player YAMLs. `random` chooses
  among the 58 names and excludes Other. Old raw tags and numeric shortcuts remain
  compatible, with unchanged manifests and campaign tokens.
- The repeatable `check_archipelago.py --frozen --options-creator` check passed
  against a new copy of the installed 0.6.7 runtime in
  `local/country-selector-041-final/`. It also generated a real seed from the
  UI-exported Ming YAML and validated the MNG manifest. The probe is installed
  only in the isolated test copy, never in the public `.apworld`.
- Eight additional stock-generator cases passed under its
  `eu4-validation/selection-cases/`: legacy name/ID (same old seed token), country
  name, display label, unlisted raw tag, Other with a custom tag, ignored inactive
  custom text, and rejection of an invalid active custom tag.

Engine acceptance and exhaustive country availability remain unverified.

## Free country selection — 0.4.0

Country selection now accepts any script-safe EU4 tag, with the same fixed
1444-11-11 start. The eight old shortcuts/numeric values remain available.
Country existence and 1444 playability are not inferred from syntactic validity.
The manifest schema and identity hashing are unchanged.

- The repository suite exercises the complete objective-option matrix for all
  eight presets plus BYZ, MNG, AZT and an alphanumeric tag (synthetic K00).
- **59 repository tests: 57 passed, two skipped** (PyYAML and AP source runtime
  unavailable), no failures. Compilation and public/tool/demo builds passed.
- Synthetic non-preset campaigns cover generated binding conditions, parsing,
  check reporting, pending rewards and acknowledgment, while rejecting a different
  player's country. Malformed tag/script input is rejected before rendering.
- The real Windows AP 0.6.7 generator emitted an MNG manifest in an isolated copy
  under `local/country-validation-040/`. The standard Launcher exported YAML and
  built the client UI. This is generator/UI evidence, not an EU4 playtest.
- The final package passed the same frozen checks with lowercase `byz` under
  `local/country-validation-040-final/`. Seven further stock-generator cases
  passed in its `eu4-validation/country-option-matrix/`: legacy `fra`, legacy
  numeric `0`, mixed-case `bYz`, custom `mng`, and rejection of `France`, `FRA }`
  and `1AB`. Legacy FRA generated the same seed token as the 0.3.1 build.
- AP-native tests cover old shortcut IDs, free-text normalization and invalid
  options; these remain source-runtime gated. The frozen generation test does
  exercise the real `TextChoice` API and World, without stubs.
- The offline CLI also accepts a non-preset tag and rejects malformed input
  without overwriting the preceding manifest. Existing PoC seed identity has a
  regression test against its original recorded token.

Live play across starting countries, fixed-threshold balance, subjects and
technology groups remain pending. The expanded protocol is in
[manual-validation.md](manual-validation.md).
